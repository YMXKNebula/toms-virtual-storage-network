# 使用与恢复

## 木桶容量

每个 Tom 的木桶相当于一个无法打开的 64 格箱子。同一种完整物品变体可以占多格；名称、附魔、耐久、药水等数据不同的物品分别保存。

每格上限取物品当前的最大堆叠。原版通常是方块 64、末影珍珠 16、钻石镐 1；堆叠调整模组会影响这个上限。掉落实体的合并数量与容器堆叠上限并非同一设置。

降低堆叠上限可能让已有库存暂时超过容量。物品会保留并允许取出，新增存入受到剩余合法容量限制。

## 仓库与网络

相邻木桶组成连续仓库，经合法连接器接入存储网络。它没有普通容器接口，不能直接连接线缆、终端、漏斗或其他机器进行物品传输。

同一仓库可以接多个连接器。终端和传输接口看到的是同一份库存，不会因为连接器数量而增加物品。

终端可以直接接在线缆上，通过有效路径到达的已加载可用连接器汇总库存。连接器可以紧贴仓库，不需要额外放一个空连接器。所有可用连接器卸载或被移除时，访问停止。

完整登记并验证过的虚拟仓库，在仓库区块卸载后仍可经有效的已加载连接器存取。加载状态变化不会自动搬动物品。普通箱子和原版木桶等外部容器保留原模组的加载限制；双箱需要两半加载。

未知线路不会被推测为连通。复杂网络的验证在预算内分步完成，期间可能暂时不可访问。离线区块被其他程序修改后，需要等实际加载才能发现变化。不同维度分别维护库存，不共享同坐标仓库。

## 拆除木桶

拆除时只结算该桶归属的物品，优先转入其他合法容量。连续拆除或复杂连通关系尚未验证完成时，物品进入持久化待转存任务；确认无法转存的剩余部分才分批掉落。

掉落任务等待目标区块加载，不会强制加载。等待任务随世界保存，正常重启后继续。断开连接不会删除库存。

## 存档与恢复

更新、备份和恢复都应以完整世界为单位，包括区块、实体、玩家数据及 `data`。不要混用不同时点的玩家背包、区块与账本。

相关目录：

```text
<世界>/data/toms_persistent_cables/
<世界>/data/toms_virtual_storage/
```

正常退出会保存线路、库存和待处理任务。强制关闭、日志损坏、世界身份不符或写盘失败时，虚拟库存可能进入保护隔离，原始文件保留。

管理员可使用：

```text
/tvsn status
/tvsn inspect
/tvsn checkpoint
/tvsn recovery export
/tomsnet status
/tomsnet inspect
/tomsnet rebuild
```

`recovery export` 导出日志、可解析状态和未决任务，供离线核对；它不会自动解锁库存或补发物品。异常后优先恢复同一时点的完整世界备份。没有完整备份时，先停止该世界的库存操作，保留原世界与诊断导出，在副本中核对后再处理。

账本无法保证玩家背包、实体与区块文件之间的绝对原子写入，因此没有忽略校验直接继续使用的开关。

## 配置与更新

配置示例见 [`config/toms_persistent_cables.example.json`](../config/toms_persistent_cables.example.json)。`enablePersistentNetwork` 必须保持 `true`。`maxResidentRuns` 是复杂度提示，不是固定线缆数量上限。

从 TVSN 0.2.2-dev 更新到 1.0.0，保留原模组 ID、方块 ID 和存档目录。正常停服、备份完整世界后替换 JAR。旧 Tom's Persistent Cables 和 Tom's Event Optimizer 不应与 TVSN 同时安装。

若要退回不支持虚拟木桶的模组，需要同时恢复安装 TVSN 前的完整世界备份。
